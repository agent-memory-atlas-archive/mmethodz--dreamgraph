# Registry Bootstrap Diary

> This node represents a chronological registry-oriented history of bootstrap activity, combining configuration identity, provider/model bindings, readiness transitions, and per-session outcomes into one reviewable record. In the neighborhood it overlaps strongly with `bootstrap_fingerprint_history`, `llm_fingerprint_history`, `instance_bootstrap_audit`, and `cognitive_bootstrap_log`, suggesting it is a unifying diary view over otherwise split bootstrap records rather than the guardrail itself. It exists to make cognitive startup behavior explainable across runs and instances, especially where `bootstrap_fingerprint_registry`, `instance_bootstrap_guardrail`, and `llm_bootstrap_lifecycle` need durable historical memory.
