# Ashoka Computer Use — capability and platform audit

**Governing rule: Use the best native capability available, and normalize the contract above it.** Native execution is selected by the adapter; shared guarantees remain above that boundary.

Date: 2026-09-30. Supporting evidence for [the unified v14.0.0 - Ashoka plan](../../../plans/graph-trust-and-agent-effectiveness.md), revision 6, C17 / F26 / NP14. Read this with the [execution design](computer-use.md). This is an audit and proposed design, not an implemented capability or a successful live-provider evaluation.

Evidence labels: **observed** means inspected repository code or a local read-only command; **documented** means the linked official documentation; **proposed** means DreamGraph design; **unverified** means a runtime/account/platform claim still needs a test. Provider documentation was retrieved on the date above. Capability discovery must recheck the selected model, endpoint, CLI, worker and account at implementation and use time.

## Platform realities and remedies

The contract uses opaque target and surface IDs, explicit coordinate spaces and worker capabilities. `HWND`, UIA, Apple AX objects, AT-SPI objects, X11 IDs, Wayland streams and browser element references belong inside backends. Windows must not define the common vocabulary.

| Environment | Documented reality | Proposed remedy and honest boundary |
|---|---|---|
| Portable controlled browser | Playwright supports Windows, macOS and selected Linux distributions. Current requirements list Node 22/24/26, Windows 11+, macOS 14+, Debian 12/13 and Ubuntu 22.04/24.04/26.04. [Requirements](https://playwright.dev/docs/intro#system-requirements). DreamGraph currently declares Node >=20 and this host uses Node 25. | Optional worker pins a tested runtime/browser combination; do not silently raise core requirements or call Node 25 officially supported. Use isolated task profiles, DOM/accessible locators and screenshots for canvas/visual checks. Same fixtures on all three OS families. Cross-platform core/browser support is a release requirement. |
| Windows native | Services run in Session 0 and cannot directly operate the user's desktop; [Microsoft](https://learn.microsoft.com/en-us/windows/win32/services/interactive-services) recommends an interactive-user process with secured IPC. [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput) is integrity constrained. [Capture](https://learn.microsoft.com/en-us/windows/apps/develop/media-authoring-processing/screen-capture) can target a window or display. | Per-user helper using UI Automation plus window capture, with input only on a usable interactive desktop and verified target. Use an ACL-bound pipe. Separate ability to capture an occluded window from ability to click it. Elevated targets, secure UAC desktop, login/unlock and secure-attention sequences require human handoff; no privilege workaround. |
| Windows lock/remote session | Microsoft distinguishes input injection from UIA-pattern operations; injected input can fail on locked/secure desktops. [UI automation](https://learn.microsoft.com/en-nz/windows/apps/dev-tools/winapp-cli/ui-automation). | Probe interactive session availability and recheck after lock, RDP disconnect/reconnect or user switch. Report structured accessibility availability separately. Use a disposable dedicated desktop/VM when shared foreground input is unsuitable, explicitly chosen by the user. |
| macOS native | Accessibility control and screen capture are separately permissioned. [Accessibility permission](https://support.apple.com/guide/mac-help/allow-accessibility-apps-to-access-your-mac-mh43185/mac), [screen recording control](https://support.apple.com/guide/mac-help/control-access-to-screen-and-system-audio-recording-mchld6aa7d23/mac). | Signed/notarized per-user helper with stable identity; proposed backend: AX for semantics, ScreenCaptureKit for scoped pixels and supported event APIs for input. Guided manual permission setup, revoke detection and Retina transforms are qualification gates. No TCC bypass, blanket background-input claim or assumption that granting capture grants input. Test protected fields, spaces and lock on actual macOS. |
| Linux Wayland | ScreenCast exposes scoped PipeWire streams; RemoteDesktop mediates user-granted input, and newer versions offer EIS. Once connected through EIS, that session uses EIS input rather than mixing legacy notify methods. [ScreenCast](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.ScreenCast.html), [RemoteDesktop](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.RemoteDesktop.html), [libei](https://libinput.pages.freedesktop.org/libei/). | Per-user portal backend: negotiate portal/compositor versions, picker/permission, stream-to-input mapping and revocation. Qualify named GNOME/KDE combinations; do not infer all Linux desktops from one compositor. No forced X11 switch or privileged `/dev/uinput` fallback. Missing input support leaves an explicitly labeled observe/browser route. |
| Linux accessibility / X11 | [AT-SPI](https://gnome.pages.gitlab.gnome.org/at-spi2-core/libatspi/) provides accessible objects/actions; application coverage varies. [XTEST](https://www.x.org/releases/X11R7.5/doc/man/man3/XTestFakeKeyEvent.3.html) defines synthetic input on an X display. Neither proves Wayland-wide input access. | Keep AT-SPI structural capabilities independent of capture/input. Optional X11 backend is restricted to an explicitly granted display; prefer a dedicated session, since application scope is a broker policy rather than an X11 security boundary. Revalidate focus and visibility; disclose incomplete toolkit trees. |
| WSL, SSH, containers, headless | A browser can be hosted away from the user's desktop. VS Code can run extensions locally, remotely or in a web host. [Extension hosts](https://code.visualstudio.com/api/advanced-topics/extension-host). | Name authority host, worker host, desktop user/session and target host separately. A Linux/remote extension host does not gain the Windows/macOS client desktop. Pair an explicitly authorized local helper or operate an isolated remote browser. Webviews are clients, not desktop executors. No ambient desktop rights via SSH or Docker mounts. |
| Existing browser / browser-to-daemon | Browser attachment shares sensitive profile state and exceeds isolated-page scope. Chrome documents Local Network Access permissions for public-to-loopback connections; its rollout notes do not establish identical coverage for every browser/transport. [Chrome LNA](https://developer.chrome.com/blog/local-network-access). | Default same-origin local Architect. Attach existing profiles only through a separately granted, tested connection; never open an unauthenticated CDP port. Test fetch and WebSocket behavior separately on supported browser versions. LNA permission does not replace authentication, Origin/Host checks or CSRF protection. |

These remedies are proposed backend choices, not promises of universal OS reach. Install/permission diagnostics should offer a concrete remedy—start the user helper, grant a named permission, choose a compatible runtime, unlock/reselect, or choose an isolated browser—and leave the original request blocked when its required capability is absent. Changing target host, isolation level, provider or mode requires visible agreement, not a silent fallback.

## Retention, cost and execution limits

OpenAI API storage controls distinguish application state from abuse-monitoring retention; `store: false` is not a universal no-retention claim. Model/endpoint/account exceptions must be checked. [OpenAI data controls](https://developers.openai.com/api/docs/guides/your-data). Anthropic also separates tool-hosted artifacts from request content and model-specific retention eligibility. [Anthropic retention](https://platform.claude.com/docs/en/manage-claude/api-and-data-retention). A local executor may still send pixels, DOM text and action arguments to a remote model. CLI/subscription policies need their own disclosure.

Image dimensions, detail, history and model affect image-token cost. Tool definitions and repeated results also consume context; caching is conditional, not a guaranteed saving. [Claude vision](https://platform.claude.com/docs/en/build-with-claude/vision), [Sol pricing notes](https://developers.openai.com/api/docs/models/gpt-6.1-sol). C17 therefore meters actual returned usage and reserves an upper bound before calls, rather than inventing a fixed cost per screenshot. No provider latency or cost benchmark was run. The [design](computer-use.md#cost-and-context) specifies how to measure it and refuse unpriced paid work.

The proposal's small JavaScript runtime needs a stronger boundary: [Node documents that VM contexts are not a security mechanism](https://nodejs.org/api/vm.html). Process separation also needs constrained filesystem/network/IPC authority; neither a small API nor a browser profile alone creates an OS sandbox. The selected baseline is structured broker operations. Generated code is deferred until a genuine isolation and mediation backend passes the same conformance suite.

## Scope of evidence and unresolved qualification

Read-only commands: `codex --version`, `codex exec --help`, `codex mcp --help`, filtered `codex features list`; `copilot --version` and relevant help; PATH discovery; dependency resolution. No CLI completion, paid request, screenshot capture, input injection, browser/profile launch, scan, service restart or live production account interaction was performed. [Machine audit evidence](computer-use-evidence.json) records hashes and observations. Existing coverage totals are unchanged historical evidence.

Implementation must qualify actual CLI image transport/native feature exposure, model/account access, model-specific retention/prices, OS helper packaging/licenses, portal/compositor versions, protected-window capture, human-input detection and local stop behavior. Unavailable test hardware remains **unverified**, never passed by mocks. These are bounded qualification tasks with owners in Slice 31, not reopened questions about whether cross-platform authority, graph integration or isolation are required.
