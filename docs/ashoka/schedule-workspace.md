# Schedule workspace — Slice 29

Verified scoped handoff; see [qualification packet](wave-24-29-verification.json). `/schedules` is a compact Schedules / Upcoming / Runs workspace over the existing durable scheduler and job owners. It does not own jobs, policy or timing. Definitions have stable IDs and expected revisions; commands retain an operation ID and original payload receipt. Selection never dispatches work.

New definitions save disabled. Enable and Run now first show a read-only preview: effective requested/resolved role models/adapters, readiness, retention, configured hard budgets, parameters, trigger policy and five next occurrences. Actual cost remains unknown without a tariff/usage measurement. A policy digest is checked at writer admission; lost-reply retries replay the admitted original before checking changed ambient policy. Preview/validation never dispatches a model or job. Editing uses the captured revision and preserves drafts on conflict. Parameters come from the core Zod action schemas; malformed parameters/JSON/cron/timezones name the field and block instead of falling back to defaults. Blank maximum runs is unlimited; zero means no runs.

Interval durations use human units, cron intent has an explicit timezone/fold/missed policy, and cycle/idle forecasts disclose dependence on future activity. Preview and actual dispatch use the same timing evaluator. UTC audit instants, configured-zone and local-operator times are displayed separately. Upcoming forecasts have a 32-day bounded horizon, at most 12 filtered definitions and explicit omissions. Timing/restart/overlap/budget semantics remain Slice 17's core contract.

Pause changes future dispatch. Cancel this run uses the captured job fence and retains unsettled/unknown effects. Run now admits a daemon-durable occurrence before responding (202); browser disconnect does not cancel it. Archive retains definition/run history and cannot cancel unrelated work. Duplicate captures the source revision atomically, creates a new disabled ID and resets counters. History displays the immutable admitted action/version/parameters/policy/config, never today's strategy label. Unknown legacy history stays unknown.

Mutation response loss retains the exact request in memory; Retry reuses it without generating another operation or automatically resending. No job credentials/secrets are written to browser storage. Canonical readback is distinct from acceptance; missing readback is reported explicitly. Poll/reconnect preserves unsaved drafts and reads current authority. The list is bounded to 500 filtered definitions, 200 retained jobs/occurrences per view with totals, and the API provides job pagination. Keyboard tabs and overflow/Shift+F10 menus preserve captured target identity; shared menu integration remains Slice 25.

The JSON ports are `/api/schedules/v2`, `/actions`, `/validate`, `/create`, `/commands`, and `/api/jobs/v1`. The legacy `POST /schedules` form port returns 410 with workspace/API links. Its toggle/default-fallback behavior is retired in this major-release staging tree. Core synchronous `run_now` compatibility remains explicit; the workspace uses preview-bound `enqueue`.

SC01–SC12 combine actual core scheduler/job tests with browser workflows, including CAS, exact replay, four triggers, DST, missed/restart recovery, cancellation/overlap and reservation accounting. SC13 uses a real disposable daemon and Windows Chromium: keyboard tabs, narrow viewport, dropped reply, offline error and canonical online recovery. Ordinary qualification is unpaid. Other-platform/browser, packaged-release and final composed evaluation remain explicit later gates.
