# Ashoka provider boundaries — implementation checkpoint

## Native CLI context admission

Architect's native CLI route retains its 128 KiB required-prompt transport ceiling. Its default context allocation is now 133,120: the full UTF-8 wire byte allowance plus 2,048 framing units. This is conservative admission allocation, **not measured model token usage**. API defaults remain 32,768; explicit session, role environment, saved profile and global limits retain their precedence and are never raised silently. Per-run cumulative input, request, retry and spend limits remain enforced.

A context-limit refusal occurs before CLI/model dispatch and reports the required allocation, configured allowance and `DREAMGRAPH_LLM_ARCHITECT_CONTEXT_TOKENS` setting. Architect pauses and recommends reviewing the context budget; unchanged retry/manual-continue actions are disabled. Narrow optional context or explicitly revise the role setting before retrying. Required graph evidence, controls and the user request are not truncated to fit. Provider-reported usage remains the settlement measurement when available; subscription usage is not invented.

## Earlier implementation evidence

Slice 8 is in progress. This document describes implemented API boundaries and role dispatch, not paid-provider qualification or completed Computer Use integration.

Daemon dreamer, semantic normalizer, tension proposal, initial-scan and enrichment routes resolve independent role settings, saved profiles and credential references. A provider binds an immutable policy snapshot; later profile changes affect subsequent bindings. The shared singleton is retained for older consumers and attached MCP sampling. A native CLI policy cannot fall through into an API provider. Unsupported settings block with a diagnostic rather than escalating reasoning or changing models.

`src/config/provider-capabilities.ts` contains versioned named API evidence. Unknown/custom names and CLI-prefixed identifiers inherit no schema, effort, tool or image guarantee. A custom model can be qualified with the role's `CAPABILITY` JSON field: exact provider/model, source/version, API list, effort list and declared capabilities. API records do not establish a native CLI worker's scope, controls or Computer Use support. API/account retention remains separate from response storage flags.

Strict output requests require qualified native support by default. Rejected native schemas do not silently switch to JSON mode or poison a process-wide cache. A caller may explicitly request `schemaFallback: "local_validation"`; this is disclosed in `outputContract` and preserves validation against the original schema. A bound role requiring strict native output rejects that fallback. Invalid schemas compile-fail before dispatch; returned JSON is validated locally using AJV and format validation. No enum case normalization or evidence coercion is performed.

Claude Messages uses `output_config.format` and `output_config.effort`. Numeric/length constraints outside the grammar subset are retained in the original local validator while adapting the wire schema. OpenAI Responses uses `text.format`, `reasoning.effort` and explicit `store`; Chat Completions remains an explicit supported option. GPT-6 tool reasoning requires Responses where documented, without automatic protocol/effort substitution.

Refusals, truncation, incomplete/paused/failed replies and invalid tool arguments raise typed provider outcomes before graph acceptance or tool dispatch. Outcomes retain available usage but omit generated partial text and raw provider error bodies. Input, output, cached input, cache creation, reasoning and total counts preserve reported meanings; absent counts remain unknown. OpenAI cached/reasoning components are not added twice; Claude input includes its three reported input components. Native tool schemas retain nested definitions/constraints and returned calls are validated against advertised tools.

Completion calls accept a cancellation signal, combined with one deadline across permitted fallback attempts. Native tool transport accepts the same signal. Broader execution ownership, admission, cancellation receipts, all client wiring and spend settlement remain Slices 6/17/18/25. Readiness uses read-only configuration/reachability checks and successful fingerprint-bound dreamer/normalizer work, without recurring paid completions. Explicit bootstrap can attempt first work without claiming prior qualification. Native Architect HTTP cancellation is propagated; a stopped pass dispatches no further tools. Bounded caller-supplied image envelopes are exercised for Responses/Chat/Messages and native tools; unknown vision capability fails before inference. Native browser Architect now binds its own role snapshot and reports requested/effective policy, with actual per-call usage including failed provider outcomes. Strict Architect pass projection is explicitly unavailable pending the Slice 25 client contract; strict provider output is implemented and tested independently. Browser image uploads currently become text/file references, so this route truthfully advertises image transport unavailable until native client wiring is qualified. Provider image support cannot imply transport support. Remaining client delivery receipts, admission and retention integration belong to their owning slices; actual Computer Use qualification belongs to Slice 31.

The existing Codex enrichment adapter now preserves an explicitly configured effort and reports unmeasured subscription usage as unknown. Both Codex paths preserve configured effort and parse native turn usage when reported. Abort reaches the child, but process-tree cancellation and independently acknowledged stop remain unqualified until platform execution work. Provider switches require an exact approved provider/model/adapter fallback; refusals/incomplete replies do not trigger fallback. Enrichment checkpoints bind the role policy and request options. No paid canary, global installation, restart or live scan has been performed.
