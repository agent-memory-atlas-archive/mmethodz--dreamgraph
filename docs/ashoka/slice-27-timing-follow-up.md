The preceding rows describe the evidence at those checkpoints. The subsequent diagnosis resolved the uncertainty about the delayed phase: the [private IPC trace](slice-27-stop-traced-root.log) recorded a real late acknowledgement around 1.7 seconds after the original Stop. [Pinned Playwright process diagnostics](slice-27-stop-native-core-debug-2.log) showed Chromium still alive after graceful close began, before directory cleanup. This was a shutdown gap, not evidence that cleanup caused the delay. The pinned runtime normally allows a much longer graceful-close interval than DreamGraph's one-second Stop contract.

The bounded correction stays inside the existing private worker. It fences input immediately, starts normal close and invokes that process's existing Playwright SIGTERM handling after 200 ms and, if still pending, 400 ms. In the pinned runtime an already-started graceful close escalates through the original browser process owner. This emits the handler event locally, so it works on Windows without forcibly killing the worker before it can return the browser's termination proof. It adds no control socket, arbitrary PID selection or model-supplied code. [Playwright documents browser SIGTERM handling](https://playwright.dev/docs/api/class-browsertype#browser-type-launch-option-handle-sigterm); the escalation behavior was also inspected in the installed 1.62.1 runtime and exercised with the actual browser.

The initial 350/600 ms attempt still missed the deadline and is retained in [the first focused result](slice-27-stop-escalation-first.json). The real-browser fault fixture drops only the graceful CDP `Browser.close` frame, leaving Chromium alive. It does not fake clocks, action replies or termination. [The corrected focused run](slice-27-stop-escalation-second.json), with [measured output](slice-27-stop-escalation-second.log), passes all 19 cases: six native graph/plan joins and thirteen browser-worker checks. Forced termination took 617.961 ms, subsequent browser requests stayed quiescent and new input was refused. Actual disconnect/watchdog recovery and original-peer lost-acknowledgement recovery also passed. Temporary verbose worker tracing was removed before this accepted focused run.

The [fifteenth complete gate](slice-27-offline-gate-fifteenth/result.json) also failed: 2,027 root cases passed, two image-envelope cases exceeded their fixture deadline, and six required graph-loop cases did not run because browser qualification timed out (in addition to the two retired particle skips). Merely shortening grace did not repair that blocking path. Another navigation-case Stop timeout was swallowed by cleanup and is retained in the log.

The bounded Windows correction is an executor-private compatibility seam for the pinned launcher. It captures the originally launched browser `ChildProcess`, matches the configured executable and pipe arguments, and launches the fixed system `taskkill.exe` asynchronously against only that original tree. It accepts no caller-supplied PID, uses no shell or public control socket, and never interprets the command's return as browser termination. Stop waits for actual browser closure, runtime cleanup and the termination helper's closure. The non-Windows runtime retains its existing process-owner signal path. The file is included in the backend source qualification digest. [Initial focused verification](slice-27-async-stop-focused.json) passed 26 cases; the stricter helper-ownership check is recorded separately in [the owned focused run](slice-27-async-stop-owned-focused.json). Neither focused pass substitutes for the complete gate.

The provider-image cases check envelope content, not a one-second inference guarantee. Their mocked inference still performs real durable admission and settlement; its finite fixture allowance is now five seconds. Product provider deadlines and the one-second Stop/five-second control-loss contracts are unchanged.

The complete gate runs one root-test worker and retains text diagnostics alongside JSON. This measures the existing functional gate without concurrent suites competing on this host; it is not a stress-load qualification. No failing test was removed or quarantined, and no new platform was added. A subsequent installed-daemon report exposed a [separate scheduler stall](slice-27-scheduler-stall.md) in code shared with the current build. Do not infer that the live daemon's load caused the browser timeouts.

The stricter [owned focused run](slice-27-async-stop-owned-focused.json) failed one of 26 cases: waiting for both the actual browser and termination helper still exceeded the old 900 ms transport allowance. It is not a passing checkpoint. Inspection of original C17 then identified a contract mismatch: the plan required held-input release within one second, while the implementation measured complete OS-process/runtime shutdown against that same second.

The maintainer explicitly resolved this on 2026-10-03: preserve one-second input release, cancellation of further actions and relinquishing control; allow up to five seconds for confirmed termination of the owned browser/worker tree with bounded escalation. This supersedes the earlier instructions in this historical record not to change whole-Stop timing. The [contract clarification](../audits/2026-09-30-coverage/computer-use.md) retains honest intermediate stopping/input-released state, unsettled lifetime and recovery-required on missing termination proof. Actual virtual page closure, rather than a local flag, proves release for the isolated backend. No new environment or backend is added.

Architect's executed script displays the intermediate state until final proof. The final complete gate remains required; these focused results do not substitute for it.
