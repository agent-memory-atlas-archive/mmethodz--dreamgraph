# Ashoka evidence publication map

The [Slice 27 closure](slice-27-closure.json) is an immutable record of the accepted system gate. Its 156 artifact paths and SHA-256 values describe the exact local evidence reviewed on 2026-10-03. Publishing the closure does not imply that every raw artifact is distributed, that a later v14 package has passed the same gate, or that its historical recorder can be rerun against changed source. Do not edit or recompute the sealed hashes to remove machine paths.

## Required for a clean checkout

`npm run ashoka:system:check -- --out <new-directory>` builds server, Explorer and editor, checks generated contracts, runs editor/root tests, and qualifies an explicitly supplied installed browser. It writes its own result, inventory, root-test JSON and logs into the new output directory. It needs `ASHOKA_BROWSER_EXECUTABLE` and `ASHOKA_BROWSER_VERSION` set to the browser actually qualified on that machine. It makes no paid model call.

The only `docs/ashoka` file read by that gate's normal build/check/test sequence is [configuration-inventory.json](configuration-inventory.json), consumed by `npm run config:check`. Regenerate it with `npm run config:inventory` after source changes and verify with `npm run config:check`. The frozen baseline check reads `tests/fixtures/ashoka/baseline.json`, verifies its embedded excerpts and hashes against the current source, and requires its named source anchors. It does **not** need `docs/ashoka/baselines/` or the historical Slice 27 output directories. Root tests also read the current baseline and the legacy plan/log fixtures under `tests/fixtures/ashoka/`. The compiled editor tests read the tracked historical specification `plans/TDD_COGNITIVE_OUTPUT_V2.md`. All other generated contract inputs remain at their normal repository locations (`src`, `packages`, `templates`, `docs/contracts`, `python/analytics`, and `scripts`).

The historical `record-27-closure.mjs` is **not** a clean-checkout gate: it reads the original result directory, prior accepted packets, source hashes and a maintainer screenshot from a local attachment path. A clean checkout should produce a new gate result; it must not regenerate or overwrite the sealed closure.

For optional offline evaluation reproduction, `scripts/benchmark-retrieval.mjs` reads [agent-evaluation-protocol.json](agent-evaluation-protocol.json) and its frozen baseline archive `baselines/d8acba015369963165acef92ad8933a02608efeb8fbde036a10d32857fec3521.json`, because the protocol's baseline hash differs from the current fixture. `scripts/evaluate-cognitive-policies.mjs` reads [cognitive-policy-protocol.json](cognitive-policy-protocol.json). These are separate offline evaluations, not mandatory steps of the system gate. The [published paid pilot](benchmarks/2026-10-03-gpt-4.1/README.md) has twelve public replay requests and reviewed results; its two private graph contexts and replies are withheld.

## Public release selection

Stage the following paths deliberately; do not stage `docs/ashoka/` recursively:

- The reviewed narrative `docs/ashoka/*.md`, except the local `sol-6.1-release-handoff.md`, plus this index. Historical notes may describe earlier pending work; the closure and release guide state the accepted release scope.
- `docs/ashoka/configuration-inventory.json`, `agent-evaluation-protocol.json`, `cognitive-policy-protocol.json`, and the exact archived baseline named above when publishing optional evaluation reproduction.
- `docs/ashoka/slice-26-closure.json`, `slice-27-closure.json`, `slice-27-offline-gate-sixteenth/result.json`, `slice-27-offline-gate-sixteenth/browser-qualification.json`, `slice-31-release-scope-conformance.json`, `slice-25-conformance.json`, and `wave-24-29-verification.json` as bounded closure/consumer summaries. Keep original bytes; do not describe unshipped underlying logs as available public downloads.
- `docs/ashoka/ui-repairs-sixth/qualification.json`, `operational-tabs-ui/qualification.json`, and `browser-23-final/qualification.json` for the current linked UI checks.
- `docs/ashoka/benchmarks/2026-10-03-gpt-4.1/README.md`, `results.json`, and the twelve `requests/*.json`. The two private comparisons expose hashes, usage and review only.
- Small directly linked historical summaries that can be included after content review: `foundation-tests.json`, `cognitive-policy-report.json`, `retrieval-benchmark.json`, `slice-18-verification.json`, `slice-19-verification.json`, `slice-31-recovery-conformance.json`, `wave-14-16-{tests,verification}.json`, `wave-15-30-{tests,verification}.json`, `wave-20-22-verification.json`, and `wave-24-29-verification.json`. These are bounded summaries; older timing/status claims keep their historical date and scope.
- When Slice 28's disposable package smoke passes, review and add `docs/ashoka/release-packages.json` (or the explicitly configured `ASHOKA_RELEASE_PACKAGE_EVIDENCE` output), together with the release artifact hashes and CI result in the final release record. This future package result is separate from the sealed Slice 27 source gate.

Keep local raw `.log`, intermediate/root-test JSON, screenshots, `*.jsonl`, diagnostic review `.mjs`, archived native review contexts and `sol-6.1-release-handoff.md` out of broad publication. Some historical Markdown links name these local artifacts; a missing public link means the local diagnostic was withheld, not that its sealed hash was changed. The closure remains a review record, while a new clean checkout can reproduce the current offline gate independently. Personal machine paths occur in many raw test outputs; they are not credentials, but they provide no value to a public release. Never publish live graph/model contexts, credentials, approvals or spend ledgers.
