# Session and transport authority

The daemon binds to `127.0.0.1` by default. Remote mode requires explicit `DREAMGRAPH_REMOTE_ENABLED=true`, a `DREAMGRAPH_REMOTE_TOKEN` of at least 32 characters and an exact JSON hostname allowlist in `DREAMGRAPH_HTTP_ALLOWED_HOSTS`. `DREAMGRAPH_HTTP_BIND` selects the interface; `DREAMGRAPH_HTTP_ALLOWED_ORIGINS` supplies additional exact origins. Host, actual listening port, socket address and browser origin/fetch metadata are checked before routes, including upgrades. Arbitrary forwarded headers and reverse-proxy port rewriting are unsupported. Remote transport encryption must be provided by the deployment; this listener serves HTTP. Bind/authentication status is exposed without the token.

Local mode trusts the operating-system user and same-machine processes. It does not isolate a malicious process running as that user. Browser sessions use an unguessable HttpOnly, SameSite=Strict cookie; non-browser HTTP callers can retain `X-DreamGraph-Session`. A remote browser establishes its session through the password form, keeping the daemon token out of URLs. Sessions expire after twelve hours; malformed, expired or rotated-principal bearers fail without silently changing identity.

Selections, Architect role preferences, history, event subscribers, terminals, cancellation and signed provider continuations belong to one principal/session. Reload with the same cookie restores preferences/history and can inspect the same running pass. Concurrent sessions cannot adopt another session's history or stop its pass. Legacy unowned histories/discipline sessions are not automatically adopted. Daemon-owned durable execution/restart attachment is still the Slice 17 job handoff; an HTTP disconnect can currently cancel its attached pass.

Native MCP transports own separate identities, sampling servers and discipline sessions. Browser-created MCP transports additionally bind the browser owner. An unknown `mcp-session-id` fails explicitly; closing a transport removes it. Node fetch's `Sec-Fetch-Mode` header alone does not turn a native client into a browser cookie owner. Stdio has an independent process-stream identity. Autonomous daemon work inherits neither a connecting client's preferences nor its sampling transport.

Native SDK/editor Computer Use inspection and controls use `/api/executions/v1/computer/` with their original private `X-DreamGraph-Session` bearer. They refuse execution bearers, cookies and browser origin/fetch-site metadata. The bounded projection composes the canonical C17 records and supplies no pixels, action arguments, provider credentials, confirmation, configuration or input dispatch. Captured endpoint/instance/execution identity remains fixed across asynchronous reads and controls. Read-only inspection cannot create a grant; lost controls remain unconfirmed until the original state is inspected. The browser Architect retains its own cookie-bound port and owner.

`session_authority.json` is private metadata under the shared physical publication owner. It stores token hashes, identities, preferences, grant challenges and grants, never bearer secrets. It does not contain graph entities and does not advance graph mutation currency. Publication/recovery and size/capacity limits apply. Configuration templates preserve remote authority fields and never create execution grants.

`GET /health` is instance transport liveness. It uses a stateless context and creates no cookie, identity, preference, grant or publication. Local probes remain independent of session capacity and interrupted graph publications; remote probes still require authenticated access and the configured host/origin policy. Execution bearers remain restricted to their original worker ports. A healthy transport response does not attest graph completeness, successful recovery or model readiness. Native clients establish their private owner separately through the authority handshake.

New-session capacity or publication-recovery failures return a closed HTTP503 response with a bounded retry hint and an explicit error. Existing identities and data are preserved. Earlier installations could allocate one twelve-hour identity per native health probe and exhaust the512-session store. The fix prevents further probe allocation; it does not silently evict unexpired identities that could belong to real users. Reuse an existing owner or allow expired ungranted identities to be reclaimed on the next legitimate creation. Do not delete the authority store to repair a health check.

Full access requires two separate browser confirmations bound to an execution, exact scope/capabilities, a digest and a finite expiry. Confirmation endpoints are not advertised model tools; browser metadata is a transport boundary, not cryptographic proof of human presence. The grant preserves truth, commit, audit, cost and native qualification constraints. The normalized Computer Use control port verifies owner/execution/target/generation/fence and requires an independent stop. Expiry/revocation aborts its signal outside the model loop; no acknowledgment means recovery required. These are control-port fixtures, not qualification of native workers or physical seats. Actual platform/seat/native stop remains Slice 31.
