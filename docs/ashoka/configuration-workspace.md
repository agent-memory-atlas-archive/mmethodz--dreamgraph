# Configuration and runtime workspace — Slice 23

The compact `/config` workspace reads the complete daemon setting catalogue. Eight keyboard-accessible tabs and global search expose scalar, enum, boolean, structured object/array/map controls, independent role settings and budgets. Unknown imported keys and launcher/client-owned keys have named read-only exceptions. Stored secrets are returned only as configured/empty markers and are never browser storage, graph evidence or model context. Empty secret entry keeps the original; removing its instance override is explicit.

All edits remain in-memory drafts until Save. A captured save binds its original revision, operation ID and whole update payload. Revision refusal retains drafts; a lost acknowledgement retains the exact request for explicit retry. Read back displays the current saved/effective values without dispatching work. Effective role profiles are daemon defaults, independent of Architect session overrides; admitted work keeps its original policy. Activation and durable save have separate outcomes, and recovered receipts never repeat activation.

Structured scheduler/event/narrative values show their actual resolved component settings and any legacy alias overrides. Editing a property includes removal of that property's instance alias in the visible draft payload; unrelated aliases and zero limits survive. Deployment aliases remain effective. Model-only saves activate only model owners and cannot restart a paused scheduler. Base model/API/retention/temperature/output settings are honored by the legacy configuration cache as well as role-policy resolution; unsupported model controls remain governed by provider capabilities.

Default, Ollama and LM Studio previews bind the selected category or all editable keys, original content revision and template hash. Preview writes nothing. Protected secrets, paths, repositories, budgets and authority policy survive. Apply and Undo stage the saved file; differences remain visible until activation/restart. The workspace displays the actual instance `dg restart` command and subsequent readback. The old unsupervised process-exit endpoint is not presented as a successful browser restart.

Root and Status embed the same canonical graph currency/debt and session-scoped job ports. Last mutation, full scan and source reconciliation remain separate; scan age does not establish staleness. Recent/active job pagination preserves owner filtering. Cancellation binds the displayed original job fence and operation ID; uncertainty retains that request and never claims underlying work stopped. Jobs retain admitted limits, committed receipt IDs, causes and unknown work. A new execution requires its original workflow rather than an invented generic retry.

Sources: `src/server/configuration-workspace.ts`, `runtime-workspace.ts`, `dashboard.ts` and the existing `schedule-api.ts`. The main API router dispatches these versioned endpoints for GET and POST; workspace tests exercise the daemon's routing order. Configuration requests preserve fragmented UTF-8 and reject invalid encoding before any save.

[The frozen root regression](slice-23-qualified-root-tests-second.json) passes 1,863 tests with two existing skips. [Actual Windows Chrome qualification](browser-23-final/qualification.json) passes 15 compiled-daemon/CLI/browser checks, including every catalogue setting, exact uncertain save recovery, zero limits, scoped template staging/undo, restart readback and shared schedules. The scan producer is an explicitly declared queued job; it establishes authoritative job state/cancellation, not numeric scan substeps or model dispatch. Native GUI, other-platform and actual-model usefulness qualification remain separate gates. Slice acceptance is recorded in the implementation log.

## Architect integration

Config, Schedules and Status are retained Architect workspace tabs. They use the same configuration, scheduler and runtime APIs as the standalone paths, share the instance session, fill the center pane and keep drafts while tabs switch. Status includes Operational status and Health views. Global template readback resolves the installed sibling templates directory. Open Explorer is a light blue link that opens its independent route in another browser tab. Browser regression evidence is in [operational-tabs-ui/qualification.json](operational-tabs-ui/qualification.json).
