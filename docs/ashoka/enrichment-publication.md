# Coordinated enrichment and source effects

An enrichment batch publishes fresh entity deltas, its index entries and checkpoint outcomes in one journaled boundary. A typed file/repository/entity key identifies every checkpoint. Current values are compared with the batch's original fields; independent human edits and new rows survive. Changed source bytes, modified generated fields or deletion produce retryable conflicts instead of overwriting evidence or resurrecting entities. Actual source evidence hashes are checked before commit. UI wrappers and original provenance remain intact.

Counts distinguish attempted, generated, committed, failed and conflicting work. Only applied deltas contribute to committed enrichment totals and later context. A failed commit does not acknowledge generated text. The operation identity binds stable intent; a committed receipt also contains its small batch result, so a lost reply can be recovered without a second model call or duplicate delta. Corrupt/incompatible checkpoints fail explicitly instead of resetting resume state.

Managed source writes publish intent and dirty scope before applying bytes. Create, edit, delete, rename and structured Markdown/source edits record before/after hashes and a durable change obligation. They report reconciliation pending rather than claiming the graph is already updated. Startup recovery observes current bytes: matching after-state restores the pending obligation, matching before-state records an unapplied failure, and mixed/unknown state remains unknown. It never repeats an ambiguous external effect. Binary deletion/rename preserve byte hashes.

A reconciliation port commits canonical deltas and the corresponding source obligation acknowledgment atomically after checking current source hashes. Dirty scope retains enrichment/digestion debt until the owning stages complete. Graph mutation time advances only with actual graph deltas; recording a source intent, checkpoint-only outcome or replay cannot fabricate graph freshness. Old full scan dates remain independent.

Durable receipt results are limited to 64 KiB. Outbox delivery uses stable event IDs and at-least-once acknowledgment: a failed sink retains pending events, and consumers deduplicate IDs. Acknowledgment uses the same journal boundary without changing graph currency. Explicit epoch retirement requires delivered notifications, matching revision and a trusted quiescence check; receipt archives remain intact. Old epochs fail explicitly, and an operation without its epoch is rejected after retirement rather than being treated as a new mutation. No automatic retirement is activated before job/client adoption in Slice 17.

Offline fixtures cover every enrichment store/checkpoint boundary, source/human concurrent edits, deleted entities, lost-result replay, wrapper preservation, source intent/effect/recovery, notification acknowledgment and archive/retired-identity boundaries. A C17 effect double uses the actual source/publication machinery to retain dispatched/unknown/observed/graph-reconciled evidence while proving its input runs once. It uses a temporary file and does not qualify a GUI worker. Remaining producer adoption, targeted execution and actual Computer Use belong to their later owning slices, including Slice 31.
