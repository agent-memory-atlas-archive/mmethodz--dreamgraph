## Closure and practical testing disposition — 2026-10-03

The maintainer directed closure of the substantially complete implementation in dependency order, preferring existing evidence and bounded correction over new qualification scope. Slice 26's converter/recovery criteria are accepted using the full-family fixtures and [exact own-instance copy proof](slice-26-closure.json). Original-instance activation remains an explicit operator rollout; the revision-7 handoff places exact packaged upgrade verification in Slice 28.

The maintainer first answered **“Defer benchmark; publish the limitation”**, then authorized a reasonable bounded real-model workload and public reproducibility. The [completed pilot](benchmarks/2026-10-03-gpt-4.1/README.md) contains all fourteen pairs / twenty-eight actual GPT-4.1 Responses calls. It preserves the original failures: incomplete lifecycle answers, trust/independence confusion, invented mutation/readback claims, age-only staleness assertions and unsupported architectural guarantees. The implementing agent reviewed the original replies; this was not a blinded or independent paid-model evaluation. The private established-graph contexts/replies are excluded from the public packet.

Collection is no longer deferred. The release claim of improved understanding remains withheld: neither GE16 nor all twelve AT task outcomes passed as model-quality benchmarks. No material understanding gain, superiority over source-only work or measured cost saving is claimed for v14.0.0. The explicit practical-testing/claim-deferral direction permits functional release closure with these failures published; it does not relabel them as passes. The evaluation owner will use community repetitions and field feedback for a patch, with tool-enabled execution, production preambles and independent review before making stronger claims. Frozen labels and spend/retention controls remain intact; no additional paid rerun is required for this release.

This benchmark disposition does not waive functional, lifecycle, authority, provenance, spending or recovery correctness. Slice 27 requires the composed existing evidence for those contracts, with its final decision recorded in the implementation log and closure packet. Slice 28 synchronizes shipped versions and verifies the disposable packaged upgrade/recovery path before release readiness. Remote GitHub execution and physical maintainer testing are reported as pending until actually run.
