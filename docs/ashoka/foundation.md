## Publication and recovery

`publication_state.json` (`dreamgraph.publication.v1`) is the internal-only final commit participant. It carries revisions, store hashes, receipts, reconciliation coverage and notification entries. `scan_state.json` remains the independent source-scan revision and structural evidence baseline. `reconciliation_journal.json` (`dreamgraph.reconciliation_journal.v2`) contains before/after images, with the publication marker last. Reads fail closed while a journal requires recovery; reads never repair it.

Epoch, actor and operation ID identify the durable receipt. Retrying the same payload returns that receipt before stale revision checks; a different payload fails. Interruption before the marker restores previous files. Interruption after it retains the committed effect even if the reply was lost. Explicit no-change operations can persist a receipt without advancing graph mutation time. Source reconciliation and full-scan markers advance independently. Unknown legacy dates remain null.

Writer ownership uses a Windows named pipe, a Linux abstract Unix socket when supported, or a loopback kernel endpoint on macOS/older supported Node. [Node's IPC documentation](https://nodejs.org/download/release/latest-v20.x/docs/api/net.html) specifies the platform behavior. The lease exposes no application API. Filesystem aliases resolve to the same instance. Busy/reserved endpoints fail closed; another endpoint is never silently chosen. This is local-host ownership, not a distributed filesystem lease. Older releases do not honor it: migration must quiesce old writers. Process-crash checks do not claim a Windows power-loss guarantee.
