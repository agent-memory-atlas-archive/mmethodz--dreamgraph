# MCP registration and result contract

The core registrars own the live inventory: **93 core tools and 31 resource URIs**. Their generated [machine catalogue](../contracts/mcp-catalog.v1.json), [tool table](../contracts/mcp-catalog.md) and SDK artifact carry exact input schemas, effect descriptions, discipline phases and compatibility limitations. The discipline manifest has **94 classifications**: those 93 tools plus the intentional local `read_local_file` extension. Plugin contributions remain separately registered; unknown extension effects cannot claim read-only qualification.

Run `npm run mcp:generate` after registration/policy changes and `npm run mcp:check` in verification. Generation calls registrars without calling handlers, starting background work or sending inference. Portable generated schemas replace instance repository hints with neutral descriptions. Authenticated `GET /api/contracts/v1/mcp` and live `tools/list` expose actual instance hints and supported contract version 1. Existing core graph schema/resource versions remain unchanged.

Both legacy `.tool()` and modern `.registerTool()` use one transport/result boundary. Original wire arguments are validated before the MCP SDK strips unknown keys. Wrong contract versions, invalid arguments, cancelled pre-dispatch requests, forbidden discipline phases and missing applicable approved plans fail before owner handlers. Owner exceptions return structured errors. A cancellation after dispatch never attests rollback; caller recovery must consult the owning operation's receipt. The catalogue distinguishes source, graph, runtime, external and private-session effects instead of labelling every analysis-named tool read-only. No generic mutation retry or generic durable commit receipt is invented.

Original content blocks, structuredContent and metadata survive the server and bridges. Legacy object-valued JSON text also becomes structuredContent while retaining its original text. Metadata states contract, tool, session, effect and outcome; it does not substitute for an owner receipt. Results above the 8 MiB machine ceiling fail explicitly without clipping. Native API prompt budgets preserve complete JSON or replace it with a whole, hash-labelled omission. An omission is not a complete answer, empty scope, failed mutation or rollback; an omitted full body is not claimed durably retained. Human previews remain separate.

Architect native API execution retains one MCP connection for a pass. The authenticated browser owner is shared with that connection, so private discipline state remains coherent across passes; native standalone clients retain their separate transport owners. Single-call CLI helpers remain compatible, return complete result envelopes and close their daemon sessions. All client discovery follows bounded cursor pages and preserves annotations/metadata. The stdio CLI bridge caches individual pages, contributes its local command only on the final page, forwards request cancellation and retains one upstream session. It never applies API continuation semantics to a CLI adapter. Its ephemeral session bearer is protected, redacted, launcher-owned and absent from model prompts.

Qualification distinguishes shared boundary fixtures from actual owner effects. The common boundary is exercised for all 93 registered names using explicitly labelled handler doubles and actual owner input schemas for invalid requests. Disposable actual HTTP/MCP and stdio entry points qualify catalogue advertisement, version/input rejection, private discipline continuity and a physical source mutation/readback. A real stdio bridge process qualifies pagination, literal structured/media/metadata and abort forwarding against a fixture upstream. These tests make no paid model requests. They do not claim every real handler's positive effect or every platform/native CLI runtime qualified; owner scenarios and final coverage remain the obligations of their slices and Slice 27.
